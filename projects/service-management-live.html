Case study

Service Management Live

A real-time dashboard that gives an IT service-management team one shared, always-current view of who is doing what, what's overdue, and where work is stuck.

RoleDesigner & developer
TypeInternal web app
Year2026
StackJS · CSS · TS · WebSockets

The problem

Work was invisible until it was late

The team tracked work across spreadsheets, chat threads and memory. Nobody had a single view of progress. Hand-offs between people got lost, overdue items only came up in meetings, and managers had to ask around to find out what was blocked.

The goal was a tool the whole team would actually keep open: fast, obvious to use, and always showing the same, current picture to everyone.

What I built

From the app

Also included: a manager oversight view, auto-archiving with Excel export, a view-only mode for wall screens, and an optional AI "Get ideas" assistant.

Hard problems

Challenges & how I solved them

01 / Data integrity

Two people saving at once wiped each other's work

Early on, every save sent the whole document. If two people edited at the same time, the last save quietly overwrote the first, with no error and no warning.

Fix: I reproduced it first: two clients each added a task, and only one survived. Then I changed saves to send only what changed. The server merges those changes into the current state per entity, so editing task 4 can't erase someone else's change to task 7. Logs merge by identity rather than being replaced, and ID counters take the highest value so two people can't create tasks with the same ID.

02 / Real-time UX

Everyone needs the same picture, instantly

A shared dashboard stops being useful once people stop trusting that it's current. Asking people to refresh isn't good enough.

Fix: I added a WebSocket channel that pushes every change to all connected browsers, so updates show up for the whole team as soon as they happen. Each view re-renders from the shared state, which keeps the UI consistent everywhere.

03 / Security

User text must never become code

Task titles, notes and feedback are all free text written by users, and they get rendered back into the page. That's a classic cross-site scripting (XSS) risk.

Fix: Every piece of user text goes through dedicated HTML and attribute escaping helpers before it is rendered. For the AI assistant, the API key stays on the server, only the typed question is sent, and the feature turns itself off completely if it hasn't been configured.

04 / Design system

Making a large UI feel deliberate

As features piled up, the interface collected inconsistent styles. At one point it used eight different corner radii, and nothing looked intentional.

Fix: I replaced them with a small set of CSS design tokens (three radii, one shared colour palette), so changing a single value updates the whole app. I also self-hosted the fonts so the app has no CDN dependency inside the bank's network, and added ARIA labels to the visual progress meters for screen-reader users.

Delivery

Shipped like a real product

  • Built through a pull-request workflow with code review and branch protection.
  • Served by a Node.js / Fastify + TypeScript backend with Zod-validated APIs.
  • Packaged with Docker and deployed to Kubernetes through a GitOps pipeline (ArgoCD).
  • Found and fixed production issues, including file permissions inside the container that stopped saves from working, by tracing each one to its root cause.

Outcome

What changed

The team now works from one live board. Overdue work comes up on its own instead of being found in meetings, hand-offs come with a notification, and managers can see the state of every project without chasing anyone.

Reflection

What I learned

  • Reproduce before you fix. The data-loss bug was invisible until I could reliably trigger it.
  • Real-time changes how you design. When updates arrive from other people, your state model has to expect it.
  • Consistency is a system, not a habit. Design tokens made the UI coherent in a way that careful hand-styling never did.
  • Security belongs in the front end too. Escaping user content and keeping secrets off the client are part of the job.
